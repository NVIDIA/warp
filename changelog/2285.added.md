Add `wp.no_grad()` to pause recording on the active `wp.Tape` and `wp.Tape.get_active()` to query it, so that library code can run non-differentiable work inside a tape it did not create. Tapes can now be nested: operations are recorded only on the innermost tape, and the enclosing tape resumes recording when the inner one exits. Previously, entering a tape while another was active raised an error. `Tape.backward()` no longer records its own operations, such as adjoint kernel launches and functions recorded with `Tape.record_func()`, on an active tape, such as an enclosing tape.

Entries of `wp.Tape.launches` are now `wp.TapeLaunch` records for kernel launches, with named properties such as `kernel`, `inputs`, `outputs`, `arrays` (including arrays in struct arguments) and `has_adjoint`, and `wp.TapeFunc` records for functions recorded with `Tape.record_func()`, including the backward pass of `wp.copy()`, with the `arrays` they access. `TapeLaunch` is a `list` subclass, so code that indexes launch records keeps working. Code that checks `inspect.isfunction()` on recorded functions must check for `wp.TapeFunc` instead.

Add `wp.Tape(strict=True)` to raise an error, instead of logging a warning in `Tape.backward()`, when a kernel compiled with `enable_backward=False` is launched while the tape is recording. Add `Tape.reset(zero_grads=False)` to discard a tape's recording and reset its array read flags without zeroing gradient buffers that other tapes still use.
