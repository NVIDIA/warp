Add :func:`warp.sparse_marching_cubes`, which extracts an isosurface directly from an implicit function (a ``@wp.func`` or a batched Python callable) by building a Lipschitz octree instead of a dense grid. Only voxels near the level set are instantiated and evaluated, so cost scales with surface area rather than volume; the whole pipeline runs on the GPU. The two stages are also exposed separately: :func:`warp.lipschitz_octree` chooses the occupied cells, and :func:`warp.sparse_marching_cubes_from_cells` runs the extraction on an explicit list of cells and their sampled corner values (useful when the occupied voxels are already known, e.g. from a vision or generative model). See ``warp/examples/core/example_sparse_marching_cubes.py`` and ``warp/examples/benchmarks/benchmark_sparse_marching_cubes.py``.
