Rename `MeshQueryAABB` to `MeshQuery` to reflect that it now serves both AABB and sphere mesh queries;
`wp.MeshQueryAABB` remains as the concrete AABB query type, now a subclass of `wp.MeshQuery`.
`wp.BvhQuery` and `wp.MeshQuery` act as kind-erased parent types: a query whose kind is only known at
runtime (e.g. selected in a kernel branch, or passed through a function parameter annotated with the
parent type) iterates via a dispatch on the kind stored in the query, while statically-known kinds
keep dispatch-free traversal loops. In the native headers, `bvh_query_t::is_ray` is replaced by a
`BvhQueryKind kind` field; `bvh_query_next()` selects the AABB traversal at compile time (native
callers of the ray path should use `bvh_query_ray_next()`), and kind-erased queries advance through
the new `bvh_query_next_dynamic()` / `mesh_query_next_dynamic()`.
