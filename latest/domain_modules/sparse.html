Sparse Matrices#

Warp includes a sparse linear algebra module warp.sparse that implements common sparse matrix operations for simulation. The module provides efficient implementations of Block Sparse Row (BSR) matrices, with Compressed Sparse Row (CSR) matrices supported as a special case with 1x1 block size.

Working with Sparse Matrices#

Creating Sparse Matrices#

The most common way to create a sparse matrix is using coordinate (COO) format triplets:

import warp as wp
from warp.sparse import bsr_from_triplets

# Create a 4x4 sparse matrix with 2x2 blocks
rows = wp.array([0, 1, 2], dtype=int)  # Row indices
cols = wp.array([1, 2, 3], dtype=int)  # Column indices
vals = wp.array([...], dtype=float)    # Block values

# Create BSR matrix
A = bsr_from_triplets(
    rows_of_blocks=2,      # Number of rows of blocks
    cols_of_blocks=2,      # Number of columns of blocks
    rows=rows,            # Row indices
    columns=cols,         # Column indices
    values=vals           # Block values
)

You can also create special matrices:

from warp.sparse import bsr_zeros, bsr_identity, bsr_diag

# Create empty matrix
A = bsr_zeros(rows_of_blocks=4, cols_of_blocks=4, block_type=wp.float32)

# Create identity matrix
I = bsr_identity(rows_of_blocks=4, block_type=wp.float32)

# Create diagonal matrix
D = bsr_diag(diag=wp.array([1.0, 2.0, 3.0, 4.0]))

Block Sizes#

BSR matrices support different block sizes. For example:

# 1x1 blocks (CSR format)
A = bsr_zeros(4, 4, block_type=wp.float32)

# 3x3 blocks
A = bsr_zeros(2, 2, block_type=wp.mat33)

# Rectangular block sizes
A = bsr_zeros(2, 3, block_type=wp.mat23)

The module also provides functions to convert between different block sizes and scalar types:

from warp.sparse import bsr_copy, bsr_assign

# Convert block size from 2x2 to 1x1 (BSR to CSR)
A_csr = bsr_copy(A, block_shape=(1, 1))

# Convert block size from 1x1 to 2x2 (CSR to BSR)
A_bsr = bsr_copy(A, block_shape=(2, 2))

# Convert scalar type from float32 to float64
A_double = bsr_copy(A, scalar_type=wp.float64)

# Convert both block size and scalar type
A_new = bsr_copy(A, block_shape=(2, 2), scalar_type=wp.float64)

# In-place conversion using bsr_assign
B = bsr_zeros(rows_of_blocks=4, cols_of_blocks=4, block_type=wp.mat22)
bsr_assign(src=A, dest=B)  # Converts A to 2x2 blocks and stores in B

Note

When converting block sizes, the source and destination block dimensions must be compatible:

  • The new block dimensions must either be multiples or exact dividers of the original dimensions

  • The total matrix dimensions must be evenly divisible by the new block size

For example:

# Valid conversions:
A = bsr_zeros(4, 4, block_type=wp.mat22)  # 8x8 matrix with 2x2 blocks
B = bsr_copy(A, block_shape=(1, 1))       # 8x8 matrix with 1x1 blocks
C = bsr_copy(A, block_shape=(4, 4))       # 8x8 matrix with 4x4 blocks

# Invalid conversion (will raise ValueError):
D = bsr_copy(A, block_shape=(3, 3))       # 3x3 blocks don't divide 8x8 evenly

Stored Block Count#

Warp computes the number of stored blocks on the device and does not automatically transfer or synchronize it to the host. This avoids the cost of a device-to-host transfer and allows graph capture. The BsrMatrix.nnz attribute is a host-side upper bound on the number of stored block slots used by sparse operations. The columns and values arrays may have additional allocated capacity. For compact matrices, the active count is stored on the device at offsets[nrow].

A topology-changing operation may leave a compact matrix’s nnz larger than the active count until BsrMatrix.nnz_sync() updates it. For example, bsr_from_triplets() sums duplicate coordinates and, when prune_numerical_zeros=True, omits zero-valued input blocks. Its nnz initially equals the number of input triplets even when the matrix has fewer active blocks. If nonzero duplicate blocks sum to zero, the result remains an active explicit-zero block until it is pruned by bsr_compress(). Entries in columns and values beyond the active count are not part of the matrix and may be uninitialized.

To get the exact count on host, you can explicitly synchronize using BsrMatrix.nnz_sync():

# The nnz attribute is a host-side upper bound
upper_bound = A.nnz

# Read offsets[nrow] into the host-side count
storage_nnz = A.nnz_sync()

Do not assume that the current value of A.nnz is exact. Before exporting a compact matrix to COO, call A.nnz_sync() and slice the row, column, and value arrays to the returned count.

Note

The BsrMatrix.nnz_sync() method copies offsets[nrow] from the device offsets array to the host, waits for the copy to finish, and updates the nnz upper bound. For compact matrices, this is the active stored block count. For padded matrices, this is the total row-capacity storage size, not necessarily the active block count. Warp reuses the transfer resources allocated by previous calls on the same matrix.

Note

During CPU graph capture, BsrMatrix.nnz_sync() performs its host readback outside the recorded stream when the matrix topology has not been changed by the capture. If the same capture has already recorded a topology update for that matrix, BsrMatrix.nnz_sync() raises NotImplementedError; read the count after replay instead.

If the stored block count has been changed from outside of the warp.sparse builtin functions, for instance by direct modifications to the offsets array, use the BsrMatrix.notify_nnz_changed() method to ensure consistency.

Row Capacity and Padded Topology#

By default, sparse constructors and topology-changing operations produce compact BSR/CSR matrices. In a compact matrix, row r stores its active blocks in offsets[r]:offsets[r + 1].

Warp also supports matrices with reserved row capacity. These matrices use row_counts to mark the active block count of each row:

offsets[row]                       : offsets[row] + row_counts[row]  active blocks
offsets[row] + row_counts[row]     : offsets[row + 1]                slack capacity
offsets[row]                       : offsets[row + 1]                total row capacity

The required invariant is:

0 <= row_counts[row] <= offsets[row + 1] - offsets[row]

For compact matrices, row_counts may be unset. In that case sparse operations infer active row counts from adjacent offsets. For padded matrices, BsrMatrix.nnz remains the storage upper bound, not necessarily the active block count. Slack entries are ignored by sparse operations, and their column and value data is not part of the matrix contract. Use row_counts to identify the active entries in padded rows.

Use row_capacity with bsr_zeros() to allocate an empty padded matrix with reserved storage:

# Reserve eight block slots per row.
A = bsr_zeros(rows, cols, block_type=wp.float32, row_capacity=8)

# Or reserve per-row capacity from a Warp array.
row_capacity = wp.array([2, 0, 4], dtype=int, device=device)
A = bsr_zeros(3, cols, block_type=wp.float32, device=device, row_capacity=row_capacity)

Providing row_capacity implies topology="padded" unless an explicit topology is passed. Passing row_capacity with topology="compact" raises ValueError. The convenience constructor bsr_from_triplets() always builds compact storage. To build COO triplets into reserved row capacity, allocate with bsr_zeros() using row_capacity and then call bsr_set_from_triplets() with topology="padded". Padded matrices created during CUDA graph capture follow normal graph-capture allocation semantics. Inside CUDA capture, use a uniform integer row_capacity or pass an explicit nnz_capacity with per-row row_capacity arrays; otherwise construction requires a host readback of the total row capacity.

Operations that may change topology accept a topology policy where supported:

compact  rebuild compact topology, discarding row padding
masked   keep the current active topology and update values only
padded   write into existing per-row capacity

The "compact" policy is the default for builders and unmasked arithmetic. The "padded" policy is an allocation contract: each destination row must already have enough capacity for the result. For bsr_mm(), reuse_topology=True is a compact-topology optimization that reuses product topology data stored in work_arrays from a previous call; it is only supported with topology="compact".

For example, a compact source can be copied into an already padded destination:

from warp.sparse import bsr_assign, bsr_set_zero, bsr_zeros

dest = bsr_zeros(src.nrow, src.ncol, src.values.dtype, device=src.device, row_capacity=src.ncol)
bsr_set_zero(dest, topology="padded")       # keep row capacity, clear active rows
bsr_assign(dest=dest, src=src, topology="padded")

bsr_set_zero(..., topology="padded") keeps row capacity only when the matrix size is unchanged. If a new size is provided, the resized empty matrix starts with no row capacity.

Padded topology-changing operations ignore row-capacity overflow by default and record status on the destination matrix. The status is sticky until cleared, so clear it before a checked operation when the caller needs to detect insufficient row capacity from that operation:

from warp.sparse import BSR_STATUS_SUCCESS, bsr_axpy, bsr_axpy_work_arrays

work = bsr_axpy_work_arrays()
y.clear_status()
bsr_axpy(x, y, topology="padded", work_arrays=work)
if y.status_sync() != BSR_STATUS_SUCCESS:
    raise RuntimeError(y.status_message())

Functions such as bsr_assign(), bsr_set_from_triplets(), and bsr_set_transpose() report status on their destination matrix the same way:

from warp.sparse import BSR_STATUS_SUCCESS, bsr_set_transpose

dest.clear_status()
bsr_set_transpose(dest, src, topology="padded")
if dest.status_sync() != BSR_STATUS_SUCCESS:
    raise RuntimeError(dest.status_message())

Because BsrMatrix.status_sync() reads device status on the host, it raises during live CUDA graph capture. Call it after the graph launch instead, keeping the matrix alive beyond the capture; BsrMatrix.clear_status() is device-side and may be called inside the capture.

Row-ordered candidate entries can be compressed with bsr_compress(). With inplace=True, matrices whose scalar type is float32 or float64 have each active row range sorted, duplicate columns accumulated, optional numerical zero blocks pruned, and row_counts updated in place using native compression support without O(nnz) temporary allocation. This path is not differentiable. Pass topology="compact" to additionally pack active blocks into compact row storage:

from warp.sparse import bsr_compress

bsr_compress(A, inplace=True)
bsr_compress(A, inplace=True, topology="compact")

With the default inplace=False, bsr_compress() rebuilds the topology natively from the active row and column data, then accumulates values with differentiable Warp kernels. By default it packs active entries into compact row storage. Pass topology="padded" to preserve per-row capacity; compression cannot increase the active block count, so this padded mode does not report row-capacity overflow. The API does not guarantee that existing storage buffers are preserved.

from warp.sparse import bsr_compress

bsr_compress(A)

When entries are generated directly into existing padded BSR row capacity, call bsr_compress() with inplace=True to sort and coalesce each active row range.

Repeated Fixed-Topology Value Assembly#

When a sequence of sparse matrices has the same compact topology and COO contribution ordering, build a BsrTripletMap while constructing the matrix and reuse it to replace only the numerical values:

from warp.sparse import bsr_set_from_mapped_values, bsr_set_from_triplets

mapping = bsr_set_from_triplets(
    A,
    rows,
    columns,
    initial_values,
    prune_numerical_zeros=False,
    build_mapping=True,
)

# Atomic-free reduction: one output owner gathers all duplicate values.
bsr_set_from_mapped_values(A, mapping, updated_values, reduction="gather")

# Atomic reduction: one worker accumulates each input value.
bsr_set_from_mapped_values(A, mapping, updated_values, reduction="atomic")

Numerical-zero pruning must be disabled when creating a reusable mapping so that its topology does not depend on the initial values. The destination dimensions and topology arrays must remain unchanged while a mapping is reused. Reusing a mapping after any topology mutation has undefined behavior, including changes made through Warp sparse APIs, custom kernels, external libraries, or a captured graph replay.

Building the mapping does not synchronize with the host, so it can be recorded in a CUDA graph. Mapped value updates are dimensioned by the host-side A.nnz upper bound; calling A.nnz_sync() once after building the mapping, outside of graph capture, tightens that bound for all subsequent updates.

A mapping built with build_mapping=True during graph capture is allocated by the graph, like any array allocated during capture. To keep the mapping independent from the graph, or to rebuild it without reallocating, preallocate it and pass it as build_mapping; it is then rebuilt in place:

from warp.sparse import BsrTripletMap, bsr_zeros

A = bsr_zeros(
    rows_of_blocks,
    cols_of_blocks,
    block_type,
    device=device,
    nnz_capacity=rows.shape[0],
)
mapping = BsrTripletMap(capacity=rows.shape[0], device=A.device)

with wp.ScopedCapture() as capture:
    bsr_set_from_triplets(A, rows, columns, values, prune_numerical_zeros=False, build_mapping=mapping)

When constructing topology without initialized values, bsr_compress() with structure_only=True sorts and coalesces row-local column candidates without reading or moving values.

Converting back to COO Format#

You can convert a BSR matrix back to coordinate (COO) format using the matrix’s properties:

# Get row indices from compressed format
nnz = A.nnz_sync()
rows = A.uncompress_rows()[:nnz]  # Returns array of row indices for each block

# Get column indices and values
cols = A.columns[:nnz]            # Column indices for each block
vals = A.values[:nnz]             # Block values

# Now you have the COO format:
# - rows[i] is the row index of block i
# - cols[i] is the column index of block i
# - vals[i] is the value of block i

If the goal is to copy the matrix or change its scalar type or block shape, use bsr_copy() instead of exporting and rebuilding the triplets. Use bsr_compress() to pack active blocks into compact storage.

For matrices with row padding, BsrMatrix.uncompress_rows() returns an array sized to BsrMatrix.nnz and uses -1 for slack entries. Use bsr_compress() first when a compact COO export is required:

from warp.sparse import bsr_compress

bsr_compress(A)
nnz = A.nnz_sync()
rows = A.uncompress_rows()[:nnz]
cols = A.columns[:nnz]
vals = A.values[:nnz]

Matrix Operations#

The module supports common matrix operations with overloaded operators:

# Matrix addition
C = A + B

# Matrix subtraction
C = A - B

# Scalar multiplication
C = 2.0 * A

# Matrix multiplication
C = A @ B

# Matrix-vector multiplication
y = A @ x

# Transpose
AT = A.transpose()

# In-place operations
A += B
A -= B
A *= 2.0
A @= B

For more control about memory allocations, you may use the underlying lower-level functions:

from warp.sparse import bsr_mm, bsr_mv, bsr_axpy, bsr_scale

# Matrix-matrix multiplication
# C = alpha * A @ B + beta * C
bsr_mm(
    A, B, C,           # Input and output matrices
    alpha=1.0,         # Scale factor for A @ B
    beta=0.0,          # Scale factor for C
)

# Matrix-vector multiplication
# y = alpha * A @ x + beta * y
bsr_mv(
    A, x, y,           # Input matrix, vector, and output vector
    alpha=1.0,         # Scale factor for A @ x
    beta=0.0,          # Scale factor for y
)

# Matrix addition (in-place)
# y = alpha * x + beta * y
bsr_axpy(
    x, y,              # Input matrix and output matrix (modified in-place)
    alpha=1.0,         # Scale factor for x
    beta=1.0,          # Scale factor for y
)

# Matrix scaling
# A = alpha * A
bsr_scale(
    A,                 # Input/output matrix
    alpha,             # Scale factor
)

Differentiating Matrix Operations#

Matrix-vector and matrix-matrix products recorded on a warp.Tape propagate gradients in the backward pass. Gradients with respect to a matrix are accumulated into the grad array of its values, at the stored blocks only, since the sparsity pattern itself is not differentiable:

A.values.requires_grad = True
x = wp.array(x_np, dtype=float, requires_grad=True)

with wp.Tape() as tape:
    y = bsr_mv(A, x)              # y = A @ x
    C = bsr_mm(A, B)              # C = A @ B
    ...                           # compute a scalar loss from y and C

tape.backward(loss)
# x.grad, A.values.grad and B.values.grad (if B.values.requires_grad) now hold the gradients

Gradients also flow to the input y of bsr_mv() and the input z of bsr_mm() when beta is nonzero. Differentiating a bsr_mm() product whose output aliases one of its operands, such as A @= B, raises a NotImplementedError.

Recorded products read their matrix operands by reference, like any other kernel input on the tape, so do not modify a matrix in place before Tape.backward(). This includes rebuilding its topology with functions such as bsr_set_from_triplets() or bsr_assign(). warp.config.verify_autograd_array_access reports overwritten values arrays. The one exception is bsr_mm() itself. While a tape is recording, a product that rebuilds the topology of z first moves z to new offsets, columns and row_counts arrays, so code that holds on to those arrays across the call sees new objects.

Batches of Vectors#

bsr_mv() also multiplies one matrix with many vectors at once. Store the vectors as the rows of a contiguous 2D array, for example of shape (count, A.shape[1]), and the result has one row per vector:

import warp as wp
from warp.sparse import bsr_mv

X = wp.ones((8, A.shape[1]), dtype=A.scalar_type)
Y = wp.zeros((8, A.shape[0]), dtype=A.scalar_type)
bsr_mv(A, X, Y)  # Y[r] = A @ X[r] for every row r
bsr_mv(A, X, Y, algorithm="columns")  # pin a strategy

Reading each matrix row once for several vectors is often, but not always, faster than separate products. The algorithm argument selects the kernel strategy: "auto" (the default) chooses one, and "loop", "rows" and "columns" pin one, which helps when the best choice for a workload is known. Pass work_buffer to reuse scratch storage across calls, for example inside a captured graph.

"auto" uses "loop" for a single vector, for transpose, for products recorded on a tape with operands that require gradients (the other strategies are forward-only and raise in that case), and on CUDA for block shapes other than 1x1 and 3x3, which were not benchmarked. Otherwise it picks "rows" on the CPU and for CSR matrices on CUDA, and for 3x3 BSR matrices on CUDA "rows" up to four vectors and "columns" beyond. bsr_mv() decides on every call and never synchronizes, so it works inside captured graphs but cannot see how many entries each row actually stores; the stored count of a compact matrix is only an upper bound on the host. Short rows favor "rows", but CSR matrices with long or irregular rows (more than about 16 entries) are often several times faster with "columns" pinned for four or more vectors.

Prepared operators such as warp.optim.linear.MultiRHSOperator and warp.optim.linear.KrylovSolve decide once at construction, where they may read back BsrMatrix.mean_row_count_sync(). On CUDA, CSR matrices with more than 16 blocks per row then use "columns" from four vectors. The choice stays fixed, including for smaller capacities from with_nrhs. The rule was fitted to finite-element and irregular matrices and may change between releases.

Kernel-level utilities#

The following Warp functions are available for use in kernels:

  • warp.sparse.bsr_row_index()

  • warp.sparse.bsr_block_index()

The bsr_row_index and bsr_block_index helpers search compact storage rows by default. Pass row_counts to their row-capacity overloads to ignore padded slack storage.

Iterative Linear Solvers#

The warp.optim.linear module provides several iterative linear solvers with optional preconditioning:

  • Conjugate Gradient (CG)

  • Conjugate Residual (CR)

  • Bi-Conjugate Gradient Stabilized (BiCGSTAB)

  • Generalized Minimal Residual (GMRES)

from warp.optim.linear import cg

# Solve Ax = b
x = cg(A, b, x=x, maxiter=100, tol=1e-6)

While primarily intended for sparse matrices, these solvers also work with dense linear operators provided as 2D Warp arrays. Custom operators can be implemented using the warp.optim.linear.LinearOperator interface.

For a complete listing of all sparse matrix functions and their signatures, see the warp.sparse API reference.

Prepared Krylov solves#

KrylovSolve allocates its workspace once and then solves many right-hand sides (RHSs) against the same system with cg(), cr(), bicgstab() or gmres(). It suits solves nested inside another algorithm and CUDA graph replay:

import warp as wp
from warp.optim.linear import KrylovSolve

action = KrylovSolve(A, nrhs=24, method="cg",
                     working_dtype=wp.float32, tol=0.01, maxiter=25)
action.solve(rhs, out)
# action.converged, action.absolute_residual, ... stay on device.

The functional solvers keep every algorithmic option; a prepared solve adds what a reusable object needs:

  • solve(rhs, out, x0=None) takes contiguous (nrhs, n) arrays, or (n,) when nrhs == 1, in the system’s scalar dtype and device. A solve starts from zero unless x0 gives an initial guess; solve(rhs, out, out) warm starts from the previous solution. Exact in-place aliasing is supported; partially overlapping views are rejected before any output is written.

  • Acceptance compares the residual with max(tol * ||b||, atol), as in the functional solvers, except that atol defaults to 0.0 instead of tol. The solvers raise atol to a safety floor of 1e-18 for a float32 working dtype and 1e-36 for float64, so atol=0.0 means a relative tolerance only, apart from a zero RHS, and the reported tolerance includes the floor.

  • Several RHSs iterate together as independent systems sharing one operator, so each reports the batch’s scheduled iteration count. This is not a coupled block method. Sparse matrices apply all RHSs with the batched warp.sparse.bsr_mv(); algorithm pins its kernel strategy.

  • update() makes in-place value changes to a sparse matrix visible, copying them into the working_dtype matrix when that differs. solve() does this on every call.

  • with_nrhs(k) prepares a smaller capacity that shares the workspace. The two must not run concurrently.

  • The device arrays iterations, absolute_residual, relative_residual, tolerance and converged describe each RHS of the latest call. stats (total iterations, maximum iterations, failed RHSs, solved RHSs) and residual_maxima accumulate until reset_stats(), which leaves the latest per-RHS diagnostics untouched. Nonfinite norms fail acceptance. solve() also returns the device arrays (iterations, residual_sq, tolerance_sq); diagnostics=False skips the per-RHS bookkeeping for short, frequent solves.

  • residual selects the residual that is reported and used for acceptance: "recurrence" reports the solver’s own estimate at no extra cost, and "fresh" recomputes ||A x - b|| with the source system and precision, which validates mixed-precision or truncated solves at the cost of one batched product per call.

M is a fixed linear preconditioner, either a single-system operator or a prepared operator with independent RHS partitions, such as a MultiRHSOperator or an FSAI application prepared for several RHSs. When the preconditioner is partitioned, pass a matching M= to with_nrhs.

Construct and warm up actions outside CUDA graph capture. Prepared replay performs no host convergence checks or work-array allocations. Eager calls from different CUDA streams are ordered automatically, but captured graphs that share one workspace must not execute concurrently. Reverse-mode derivatives through prepared solves are not supplied.
